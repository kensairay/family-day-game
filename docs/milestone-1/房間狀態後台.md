# 房間狀態後台

新增日期：2026-10-06。正式前端入口 `/?rooms`；使用目前的管理密碼登入，沿用一小時HttpOnly工作階段。

[Staging房間狀態後台](https://family-day-game-staging.ompstw.workers.dev/?rooms)

## 操作

1. 從題庫後台、主持人入口或成績後台按「房間狀態後台」。主持人遊戲分頁的「開啟房間狀態後台」會另開分頁，保留原本主持人連線。
2. 登入後會顯示尚未到期的房間，包含已完成或手動關閉的房間。每頁十間，使用上一頁／下一頁查看。新房間通常出現在第一頁；按「重新整理房間清單」回到第一頁並更新目前選取的房間。
3. 按「查看房間狀態」開啟詳細狀態，或輸入八碼房間代碼查詢。已到期房間不在清單內，但只要曾登記仍可按代碼查詢。
4. 按「重新整理此房間」取得最新資料。顯示的是查詢當下的狀態，不會自動輪詢。

## 顯示資訊

| 資訊 | 說明 |
|---|---|
| 房間代碼、題庫與發布版本 | 使用房間建立時的題庫快照；後來修改或封存題庫不影響顯示 |
| 房間狀態 | 開啟中、已完成、已關閉、已到期 |
| 遊戲階段 | 等待開始、答題中、等待公布、答案已公布、回合結束、完成、關閉 |
| 在線／已加入人數 | 在線依有效WebSocket及心跳租約計算；尚未連線的預留名額不算已加入 |
| 主持人連線 | 有有效主持人WebSocket才顯示在線；已關閉／到期顯示離線 |
| 題目進度 | 目前回合／題數、總題數及已公布題數；不包含題目內容、選項或正解 |
| 時間 | 建立、開始、到期、作答截止與查詢時間；全部顯示台北時間 |
| 成績歸檔 | 尚未結算、等待歸檔／已寫入人數、已完整歸檔；可前往成績後台 |

本版沿用共享管理密碼，所有已登入管理員皆可查看房間；尚未新增個別主持人帳號或房間擁有者權限。查看頁面不提供控制遊戲／接管主持人功能，不讀取、回傳或儲存主持人token；遊戲操作仍在原主持人分頁。

## API與資料

- `GET /api/admin/rooms?cursor=...`：十間房間的狀態與下一頁游標。使用RoomDirectory既有的尚未到期登記，每頁最多十次GameRoom RPC，不掃描全部Durable Objects。
- `GET /api/admin/rooms/:roomId`：按已登記房間代碼取得狀態。先查known_rooms，再取得GameRoom；不存在的代碼不配置物件。
- 房間狀態來自GameRoom SQLite與有效WebSocket附件，不使用D1歸檔倒推即時狀態。
- 沿用管理員Cookie、HTTPS、後台IP限流與`Cache-Control: no-store`；房間／玩家Bearer token不能存取後台。
- 查詢不寫入遊戲狀態、不延長租約、不啟用玩家、不取代WebSocket。截止時間已過時顯示有效的收題階段，但不藉查看動作推進或修改儲存資料。
- 某一間房間無法回應時，清單保留該代碼並標示暫時無法讀取，其他房間仍顯示。
- 到期或跨分頁登出時清除房間清單、詳細狀態與輸入代碼；登入失效後的延遲回應不可重新填入畫面。
- 只新增RoomDirectory的SQLite查詢索引，不需要新的D1 migration，不變更已有題庫、房間題目或Prototype。

## 驗證

`npm run test:rooms`使用隔離Miniflare；瀏覽器驗證合併至既有`connection.e2e.cjs`，由`npm run test:admin:browser`與遠端`npm run staging:verify`執行，涵蓋Chromium／WebKit的房間檢視、不中斷主持人、三回合狀態／歸檔、375px排版、玩家拒絕讀取、跨分頁登出與遲到回應攔截。各部署版本的最終結果以GitHub Actions紀錄為準。
